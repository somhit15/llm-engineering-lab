# LLM Engineering Lab

A hands-on workspace for learning and building LLM applications, starting with **LangChain** and later expanding into **LangGraph**.

The project is designed around small, runnable experiments rather than one large application. Provider-specific integrations are kept separate from application logic so you can compare models without rewriting your experiments.

## Learning path

1. Chat models and messages
2. Prompt templates and structured output
3. Tools and agents
4. Retrieval-augmented generation (RAG)
5. Conversation history, tracing, testing, and evaluation
6. LangGraph: stateful workflows, branching, loops, persistence, and human approval

## Requirements

- Python 3.12 (recommended baseline)
- [uv](https://docs.astral.sh/uv/)
- An API key for at least one supported provider: Google Gemini or NVIDIA API Catalog

## Quick start

```bash
git clone https://github.com/somhit15/llm-engineering-lab.git
cd llm-engineering-lab

uv python install 3.12
uv sync

# Copy the template, then add your own key(s).
# macOS/Linux:
cp .env.example .env
# Windows PowerShell:
# Copy-Item .env.example .env
```

The first `uv sync` resolves compatible package versions and creates `uv.lock`. Commit that lockfile after setup so future installs can reproduce the resolved environment.

Edit `.env` and set the provider, model ID, and matching API key. Never commit real credentials.

Run the first example:

```bash
uv run python -m langchain_learning.experiments.first_model
```

Run tests and linting:

```bash
uv run pytest
uv run ruff check .
uv run ruff format --check .
```

## Provider configuration

In `.env`, choose one provider and a model ID that your account can access.

Gemini example:

```dotenv
LC_PROVIDER=google_genai
LC_MODEL=gemini-2.5-flash
GOOGLE_API_KEY=your_key_here
```

NVIDIA example:

```dotenv
LC_PROVIDER=nvidia
LC_MODEL=your_nvidia_model_id
NVIDIA_API_KEY=your_key_here
```

Model IDs, access, quotas, and free-tier terms can change. Confirm current availability in [Google AI Studio](https://aistudio.google.com/) or the [NVIDIA API Catalog](https://build.nvidia.com/).

## Project layout

```text
.
├── .env.example
├── .gitignore
├── pyproject.toml
├── README.md
├── src/
│   └── langchain_learning/
│       ├── __init__.py
│       ├── config.py
│       ├── models.py
│       └── experiments/
│           ├── __init__.py
│           └── first_model.py
└── tests/
    └── test_config.py
```

After your first `uv sync`, `uv.lock` will also appear at the project root.

- `config.py`: reads and validates provider/model settings.
- `models.py`: one place to initialize a provider-backed chat model.
- `experiments/`: small learning exercises, added in sequence.
- `tests/`: fast tests that should not require paid API calls.
- `pyproject.toml`: project metadata and dependency declarations.
- `uv.lock`: exact resolved dependency versions, generated by uv.


## Learning principles

- Prefer current [LangChain documentation](https://docs.langchain.com/oss/python/langchain/overview) over copying older tutorials verbatim.
- Understand the underlying concept, then implement it yourself.
- Keep secrets out of source control.
- Test application logic without calling an LLM; keep live provider checks as explicit manual experiments.
- Add dependencies only when a lesson needs them.

## Security

`.env` and local virtual environments are ignored by Git. Use `.env.example` only for placeholder values. If a key is exposed, revoke it with the provider and create a replacement.
